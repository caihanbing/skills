# Specialist routing

Discover each named skill in the active environment and follow its actual instructions when applicable. Explicit user choices take priority; do not silently install missing skills. If a needed skill is unavailable, report the limitation, continue independent work and do not claim its checks ran.

- **Code implementation, fixes or refactors:** invoke `$ponytail` when entering actual coding. Use its default `full` level unless the user selected another level or stopped it. Clarify material decisions first; minimal implementation never overrides scope, security, accessibility, error handling or necessary tests. Respect its session-level behavior. Pure documentation work does not activate it.
- **UI design or modification:** invoke `$impeccable` and route to the playbook matching the actual request. Narrow refinement preserves existing visual identity; new surfaces and redesigns follow its context and planning rules. Respect read-only scope and any explicit confirmation rules. UI critique does not replace code review or functional tests, and a read-only review does not authorize fixes.
- **Technical visualization:** invoke `$archify` when requested or when a complex architecture, call chain, asynchronous state or data relationship is materially clearer as a diagram; reuse a correct existing artifact. Read-only analysis does not create files. Follow Archify's repository evidence rules: if relevant source paths have uncommitted changes, defer the evidence-backed diagram until committed, explain the limitation and never commit automatically. Unrelated dirty paths do not alone block the diagram. Store durable diagrams in the feature's repository-local asset directory and preserve a textual explanation in its Feature Doc.

Complete design, review and diagram artifact writes before entering `verifying`. If subsequent implementation-state changes invalidate the recorded basis, return to implementation as required and repeat verification. Do not broaden worktree-digest exclusions. At closeout call `$manage-feature-docs` in archive/update mode, not as a new development request; only a newly discovered substantive issue returns work to implementation.
