# CodeFree 任务执行

当用户要求用 codefree-o 执行已有计划时使用。读取 [CLI 与恢复流程](references/cli.md)，用本 skill 的 `scripts/runner.py` 记录计划、基线、执行和审查。结合当前 CLI 帮助核实兼容性。

整理最新计划、验收标准、项目绝对路径、项目规则、既有改动和授权，缺失关键信息时补齐。用户指定模型优先，否则使用 `glm5.3`；只使用实际模型列表中的唯一匹配，不擅自切换。每个新建会话的标题反映当前任务，续接使用确切会话 ID。交接限定任务范围及已有授权，不传无关隐私或凭证。

派发前按执行顺序拆分任务，为每项写清目标、修改位置、依赖、具体步骤、验收以及验证命令和预期结果，按 CLI 文档生成结构化清单。结合代码核实内容足以独立执行，字段齐全不代表内容具体。批量交给 CodeFree 顺序完成；影响行为或兼容性的未决问题须先澄清。首次和重建交接写明项目规则、用户既有修改与授权；修正反馈写明任务 ID、证据和复验要求。

启动运行后优先等待宿主完成通知；没有通知时使用工具允许的最长等待（本环境单次最多 60 秒），仍在运行则直接继续等待。等待期间不主动查询状态、读取日志、检查工作区或反复分析；用户主动询问、工具报错或进程结束时再处理。完成后先读取摘要，异常或证据不足时才读取相关日志。等待本身不能保证 Codex 额度为零。

将实现和修正交给 codefree-o。Codex 审查实际变更，核对用户既有修改是否保留，并按验收标准执行适当验证。每轮记录通过、失败或阻塞及证据；未核对基线保护前不得标记完成或继续派发。失败时反馈具体问题、证据、期望行为和复验要求，优先续接；会话不可恢复时保留证据并提供完整上下文重建。

正常续接只发送增量上下文，等待进程结束后先读摘要，仅在异常或证据不足时读相关日志。不统计或限制 codefree-o 额度；以验收项通过、问题复验关闭或阻塞解除并推进验证作为实质进展，代码量增长及重复失败不算进展。有进展时不设总轮数，连续三轮无进展或遇到登录、权限、服务等阻塞时暂停，保留恢复信息并如实报告。

最终报告实际模型、轮次、审查与验证证据和剩余问题。不得因委托扩大用户授权。
