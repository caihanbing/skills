# Test Gate

> 唯一源：dms-console 仓库 `docs/skills/dms-test-gate/`，含 `agents/` 两项可选专职能力。规则修订：`test-gate-2026-10-25-r3`。使用副本时核对实际加载路径、规则版本和包指纹，不假定其他会话已重载；历史结论保留原规则版本。

检查本次应验证的行为是否有可信证据。三个质量动作是：**明确关键场景 → 验证行为与测试有效性 → 核对结果并完成必要复审**。动作不绑定固定表格、人员或审批；授权与完成边界见 [工作流契约](../dms-dev/references/workflow-contract.md)，证据及重验规则见 [任务契约](../dms-dev/references/task-contract.md)。

主会话负责范围、场景及最终核对，按需委派。先明确业务期望，再写目标测试；已有实现或测试直接承接，披露场景后补并从原始需求重新核对，不删除实现来补造顺序。当前宿主强制的调用限制优先；自动发现不增加写入、测试副作用或外部操作授权。

## 分级与适用范围

在结论中说明等级及依据，按改变的行为和失败影响判断，不以改动行数或文件后缀代替。拿不准的具体风险先补调查或证据，不机械扩成最高档全套流程。

先按[工作流契约](../dms-dev/references/workflow-contract.md#授权与阶段)确认可行性实验与正式交付范围。实验用下列分级选择适用验证，按限定问题报告结论、证据和限制；实验完成不代表正式交付门禁通过。本次明确要求完整开发门禁时，仍须核对全部适用必需项。

| 档 | 判据 | 必要验证 |
| --- | --- | --- |
| L0 | 文档、注释、格式、只读分析 | 内容及适用格式核对；规则语义变化按工作流契约检查，不宣称代码门禁通过 |
| L1 | 保持对外可观察行为的局部调整 | 相关基线、前后行为对照及受影响回归 |
| L2 | 一般可观察行为变更，如功能、缺陷修复、默认值调整 | 改变的行为、重要边界/失败场景、直接依赖的不变量及受影响回归；不自动要求独立 agent |
| L3 | 权限、租户隔离、资损、数据丢失、并发、发布流程或关键框架机制改变 | 对应真实入口/集成证据及一次综合独立复审 |

适用项目规则或本次明确要求的独立复审继续执行，包括安全敏感、公共接口、迁移、宽范围重构、大写入集和重大未决风险；不能靠定为 L2 绕过。等级改变须说明行为与风险依据。

L1 的行为保持主张须有对照证据；重命名或移动接口导致旧版无法直接编译时，可用适配后的相同输入输出比较或已有特征测试，不因编译失败自动升档，也不能把它算作行为一致。发现真实行为变化则按 L2/L3 核对；主张仍无法验证时保留缺口。

## 一、明确关键场景

复用已批准需求、决定、契约和有效场景分析。普通任务用简短清单或一张表记录 **场景、期望及依据、验证方法、结果** 即可；状态流转、多个条件相互影响时补对应表格，不固定要求四张表或全量历史挖掘。

- 场景描述可观察的业务行为，期望须能判定对错。区分需求/批准契约、开发者意图及实现线索，注明可查来源；代码结构或运行现状不能单独证明业务应该如此。
- 范围是本次改变的行为、直接依赖的不变量和受影响回归。共享守卫、跨模块配置或框架机制须追到实际消费者和接入方式；不因 L2 自动重验整个业务闭环，也不因只改一个模块漏掉直接影响。
- 配置或默认值调整核对修改值、未提供值的行为及适用覆盖优先级；验证到真实消费者即可回答的问题，不扩成无关生命周期测试。
- 场景遗漏风险或业务复杂度足以支持委派时，可使用 [测试分析者](agents/test-analyst.md) 独立补充；通常由主会话完成，不把自出清单称为独立分析。
- 待决问题先查既有依据。仍会实质影响业务、权限、兼容性或验收时，集中提出具体选择与推荐；只暂停依赖答案的工作。保留原始问题、处置依据和对应目标，不能把“问过但未答”记为已验证。

原始需求、修订、排除范围、验收、反例及决定保存一次，关联来源和版本；普通复审可查原文，不能只收到主会话结论。材料仅在获准位置保存，简单任务可用对话。场景清单是已调查范围，不宣称业务场景全集。

## 二、验证行为与测试有效性

优先复用或扩展现有测试；新增测试须针对本次具体错误或重要回归，补充已有检查未提供的证据。测试通过、覆盖率高或名称匹配，均不单独证明目标已验证。

| 改动 | 最小有效性依据 |
| --- | --- |
| 缺陷修复 | 优先已有复现或同一目标在旧实现失败、修复后通过；失败原因须对应原错误，多处修复不自动要求逐处变异 |
| 新行为 | 独立需求/固定夹具导出的精确结果，以及会改变结论的边界或拒绝场景，在实际被测入口执行；可用真实先红后绿，但无旧版对照不自动要求变异 |
| 保持行为的重构 | 相关基线、相同输入输出对照和受影响回归，不为取红破坏正确基线 |

核对实际入口、前置条件、断言和副作用。避免恒真断言、mock 被测机制后自证、在测试内复制生产算法互证、吞掉异常或只断言“不报错”；mock 可以隔离无关依赖，不能冒充它替掉的机制已获验证。

**出现具体有效性疑点时必须补证**：已知目标错误仍全绿；断言无法区分不同业务结果；其他守卫或同类异常可能冒充目标；mock 替代了所声称验证的机制。先明确其他前置条件、加强结果/拒绝语义/无副作用断言或改用真实入口；仍不能排除该具体错误时，再做有针对性的隔离回退、故障注入或变异。不能仅因“新功能没有旧版本”要求变异，也不能用风险低免除已发现缺口。

需要反事实或变异时：

- 编译、环境或无关失败不算目标错误被检出。并发/时序问题尽量控制交错并说明失败归因，不能反复跑到绿来消除已观察到的失败。
- 记录目标错误、实际补丁位置、预期与实际失败用例及失败原因。文本替换先核对锚点唯一性或精确位置，并检查实际 diff；不能只看失败总数。发现错位，核对受同一定位方法影响的锚点，失效证据重做。
- 一份共用守卫注入可支撑多个场景，前提是各场景前置条件成立、各自断言了业务结果；不要求失败清单互不相同。破坏 DAO 等必经点造成普遍异常，只能证明经过该处，不能证明各业务规则有效。
- 存活变异及异常失败如实保留。等价变异须说明对本次输入域为何无可观察差异；仍存在关键敏感性疑点则换有效错误构造，不把存活自动算缺陷或自动豁免。
- 若失败依赖兜底、默认值或其他旁路行为，记录该前提；前提改变时重验相关证据。
- 回退或注入只在可丢弃副本/已授权隔离工作区执行，禁止覆盖用户工作区。执行前后核对状态，保留必要证据；清理按所有权及授权处理。不删测试或弱化断言转绿。

## 三、核对结果与必要复审

按任务契约维护同一份有来源的 `expected_checks`，在运行前固定测试身份、筛选条件及参数集合，再核对实际发现、执行与报告。记录真实命令、用例明细及框架统计；`testFailureIgnore` 等导致退出码恒 0 时，以框架失败/错误计数判定，不能把 `BUILD SUCCESS` 或管道末端状态当通过。必需项 missing、skip、disabled、aborted 或参数不全不能放行；已有 FAIL 不能被可选标签或缺失项抹掉。

执行目标测试及受影响回归；重构和大改动先核相关基线。复用充分且仍有效的证据；出现失败或抖动时，对照基线定位。

新增代码按[任务契约](../dms-dev/references/task-contract.md#新增代码覆盖率)的职责和计量规则验收：应用及业务共享库保留现行 **80%** 要求；发布、部署、运维编排及专用辅助逻辑按行为、风险和适用集成证据验收，可信覆盖率作辅助。根据代码的实际用途和调用方确定验收要求。

核对明确的数值目标、报告义务和获准调整的范围。新证据表明计量方法不可靠时，按契约评估影响、提出方案和推荐。其他必需检查仍须满足，目标调整不自动产生 PASS。

改变 AOP、事务、拦截器、条件装配等框架机制时，须有真实框架上下文及消费点证据，例如最小 Spring 测试切片或启动后真实调用；直接 `new` 或手工造代理不能替代。发布、权限和跨边界链路按本次验收验证实际接入与拒绝后的终止路径；模拟只证明模拟范围，不冒充真实部署或生产结果。

### 综合独立复审

L3、适用项目规则或本次明确要求时，由新的只读审查上下文检查需求、实现、测试和原始结果。先按需求/契约核场景，再看实现及断言；检查实际入口、关键错误能否检出、必需检查完整性及历史问题处置，不能只看 diff 或代码风格。

这是 Code Reviewer（代码审查者）的综合职责，不要求对实现盲，也不默认启动 `dms-review-changes` 的整套委派；该 Skill 适用时按自身范围使用。同版本、同范围且职责齐全的一次复审，可同时满足测试充分性、L3 和交付审查。主会话自查不能替代必需独立复审；普通 L1/L2 没有上述触发条件时，由主会话完成核对。

保留完整原始审查结果及证据引用，反馈先核实，修复后复核受影响部分。可续用原审查者；无法续接时允许新审查者接手，但须交接原发现、处置、当前版本和未决项，不清除失败历史。材料过大时只按可证明独立的行为拆分，每份有共同需求索引和相关完整材料，最终核对无遗漏及跨部分依赖；不可拆或缺关键材料时保留 INCONCLUSIVE。

### 可选严格盲审与角色适配

[Test Analyst（测试分析者）](agents/test-analyst.md) 用于确有必要的独立场景分析；[Test Reviewer（测试评审者）](agents/test-reviewer.md) 仅用于本次明确要求的严格测试盲审。两者是专职材料契约，不是所有 L2/L3 的固定前提。工具调用标识为 `test-analyst`、`test-reviewer`，实际宿主适配另行核对。

启用专职角色时，仍须满足其材料和实际隔离要求：分析者只读且不接触目标测试；盲审者不接触待审实现，判断所需材料完整内联，禁用全部工具。原文含禁看内容时保留原文并报告限制，不裁剪造盲态。规则源或 TOML 更新不改变宿主内置角色契约，不能借同名源码或普通复审绕过旧角色限制。

可选能力不可用时披露，普通流程可继续；本次已将独立分析或严格盲审列为必需时，缺少材料/隔离或未返回有效结论仍阻断该项。重试须有原因并遵守现行预算与失败规则，不自动换工具、外部服务或用户可见会话。

## 证据复用与结论

任务相关修改后先撤销最终 PASS，按任务契约列出受影响目标、入口、断言/夹具、实现及依赖，重验/复审对应部分；说明保留证据的前提为何仍等价。共享守卫、helper、配置或框架变化须追到相关消费者，边界不清时扩大到相关消费范围。补证后重新核对完整必需检查和最终集成快照，形成新版本结论，不自动恢复旧 PASS。

简短报告等级、范围、职责及验收方法、关键目标与实际结果、适用数值或计量限制、报告交付状态、复审结果/原始记录位置和剩余限制；有阻断时给出具体方案与推荐。历史失败、存活变异及待决处置保留，不反复内联全部历史材料。

- **PASS**：本次全部适用必需检查有效完成，没有未解决失败、期望未决或必要证据缺口；适用独立复审已闭环。
- **FAIL**：已观察到本次不合格，列明目标和证据；其他缺失项单列，不把失败改成未知。
- **INCONCLUSIVE**：必要期望、材料、执行或必需复审不足以作结论；只暂停依赖部分，独立已授权工作继续。

历史结论保留当时版本与限制；新规则只能用于明确的新版本评估，不能追溯把旧 INCONCLUSIVE 改成 PASS。必要检查完成后交付，不因阶段切换或角色数量不足追加无关验证。
