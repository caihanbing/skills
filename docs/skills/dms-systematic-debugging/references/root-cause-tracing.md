# 反向追溯根因

从错误暴露点沿调用链反向追到最初产生坏值、错误状态或污染的地方，再在来源修复。适用于堆栈深、数据跨层传递或不清楚污染来源的问题。

记录症状、直接原因、各层输入值和最早异常点。每层只问：该层收到的值或状态是否已正确；若不是，继续向上追。只有无法再取得判别证据时，才在当前层防护，并说明限制。不要仅在错误暴露处掩盖症状。

无法直接追踪时，在危险操作之前加入最小、可移除且不含敏感数据的诊断信息，关联关键参数、请求或任务身份、时间和调用链；采集后确认诊断本身未改变场景。能使用调试器时优先观察真实变量。测试污染可用隔离的、逐步缩小的运行范围定位来源，不能把忽略失败的退出码当作通过证据。
