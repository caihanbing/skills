# 条件轮询

异步测试或偶发超时时，等待可观察的业务条件成立，而不是猜测固定等待时间。轮询应有明确超时、合理间隔和能说明所等条件的失败信息；每轮重新读取状态。

先复用项目已有的等待工具。若没有合适工具，不为一次等待擅自引入依赖；采用最小、可维护的测试辅助方式，并遵守当前项目规范。被测对象本身是已知时序时可以使用固定等待，但应先等待触发条件，并说明时长来自何处。
