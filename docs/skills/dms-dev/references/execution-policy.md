# 执行与恢复策略

契约版本：dms-dev-v3.1。状态和任务交接字段见 [任务契约](task-contract.md)，角色与授权见 [工作流契约](workflow-contract.md)。本文件不提供调度服务或强制隔离，具体控制由实际宿主能力及运行证据建立。

## 选择执行方式

默认由主会话连续执行；只有独立输出、接口已清楚且材料与写入可隔离的工作才委派。主会话负责需求、关键决定、总进度、门禁安排、集成与最终验收核对。子任务不递归委派，也不代做独立评审。

同一工作区默认单写入者，包括主会话。并行写入用独立已授权工作区，约定文件所有权、输入快照和集成责任；不同文件仍需核对数据库、端口、测试数据、构建输出与全局配置。无法隔离则串行。独立只读工作可并行；元数据写入许可不等于主会话可同时改业务范围。

新工作区不天然包含未提交、未跟踪、忽略配置及依赖。按授权构造必要输入，不复制凭据/他人 index/整个工作区。创建失败只有在当前工作区已满足授权及隔离时才可串行替代，否则阻断受影响工作。保留无关修改，不擅自改忽略文件。

## 委派、前置分析与返回

派发前主会话核对适用档位、已授权输入、依赖、基线、测试入口、共享资源与剩余预算；先明确关键场景再派写目标测试，通常由主会话分析，复杂业务或明确遗漏风险时才委派。已有有效分析直接复用；已有测试披露后补顺序，不伪造事前分析。主会话亲自实现也遵循此原则。

每次委派交付完整任务交接信息、原始要求、允许材料、准确路径/所有权、验证和停止条件。只传最小完整上下文；不能为了省成本删掉角色必需原文，也不全量继承实现者推理给独立审查。

worker 中途发现缺少必需 check_id、前置材料或需独立复审时，返回触发依据、允许材料、缺项、待继续位置及活动进程，暂停依赖动作并交回控制权；不自行派人，不等一个尚未通知主会话启动的角色，不跨必需检查继续。主会话按实际触发条件安排综合复审或满足专职隔离契约的角色，核对结果/旧写入/版本后续接；不因普通 L2 自动追加角色。新执行用新 attempt，失败次数继续累计。

核对返回身份仍有效、真实修改未越界、证据属于输出快照且实际执行。旧 attempt、已取消或输入过期的返回只留历史，不推进当前状态；复用其代码须重新核对、集成并验证。返回补丁不增加应用、合并或提交授权。

## 预算与失败

派发前按当前适用规则说明并登记有限预算：并发、顶层执行、内部委派、必需角色、修复/复审预留。先计算必需角色，不能耗尽预算后省掉质量要求。具体模型、档位、上限及登记方式在宿主适配维护，不能把调用次数当账号额度。

超计划先说明新增问题和必要性；达到预算停止受影响的新派发，安全处理已启动任务，保留未完成检查。无法硬拦截的限制称调度约定；配置/提示词不能证明实际模型或推理档位已切换。用量不可见记 UNKNOWN，不猜套餐百分比或擅自切模型/付费服务。

同一 issue 的实际修复验证失败跨主会话、worker、attempt 和恢复累计：第一次换思路；第二次继续换思路并说明困难；第三次暂停该问题与成员讨论，不做第四次。新尝试须有新证据/假设或不同方法。只读调查、预期业务失败取证、无关既有失败不计数；环境受限先定位限制并尝试已授权替代或正式申请权限，仍受限记阻断，不冒充修复失败。独立已授权工作继续。

## 停止、接管与恢复

暂停、取消、用户接管或业务变化时：先停止相关新派发并使旧执行不再推进状态；通过授权宿主机制停止/接管 worker；核对其测试、构建、数据库动作等子进程及副作用。关闭线程不证明已止写。不能猜 PID 杀其他会话，也不因取消删用户文件或自动回滚。

恢复按依赖顺序核对：

1. 当前授权、规则与记录/实际 `package_id`；包变化时核对旧字段、语义、角色材料/权限及证据兼容，保留旧包与迁移依据。
2. 唯一协调权，活动 worker/子进程和共享资源；没有可靠交接或观测时保持共享范围 BLOCKED，只继续已证明独立的只读/隔离工作。
3. 实际工作区、未提交改动、记录完整性与有效证据；损坏记录按任务契约重建。
4. 只续未完成部分；已实现未验证只补验证。旧写入停止或隔离、版本明确后才在同范围重新派写入。

`coordinator_epoch`、任务 ID 或停止指令只是核对资料，不保证恰好执行一次。旧任务资源不能固定旧包时不得在旧会话混用新契约；升级后须新会话载入并显式迁移，不能因改 package_id 就沿用旧证据。更新安装的维护/回退步骤属于宿主适配，首版不热升级。

## 集成与交付

集成前核对输入基线、输出范围、共享接口、冲突及活动写入者。只应用已授权必要改动；冲突按原始要求解决，不自动全选一侧。组合产物、解冲突、改共享配置/依赖后验证受影响接口、端到端行为和回归，审查最终范围。局部证据只能作为输入，复用须证明范围/前提等价。

按工作流契约交付完成/未完成范围及验收资料，保留证据和用户工作区。没有 Git 或发布授权时停在待验收；未满足必需证据时保持 NOT_READY，不用“实现完成”掩盖整体阻断。
