# 任务与证据契约

契约版本：dms-dev-v3.1。小型串行任务用一段说明即可；复杂、委派或跨会话任务复用既有计划与获准证据位置，例如 `.dms-dev/runs/<case-id>/progress.md` 和必要 `evidence/`。只读任务用对话或已批准输出位置，不自行写项目/忽略配置。续接从已有记录的未完成项和下一步开始；当前上下文已加载、身份与适用范围未变的规则、决定及证据直接复用，缺失或前提变化时只补读相关部分，不因换轮重建调查和检查清单。

## 最小记录

| 对象 | 必需内容 |
| --- | --- |
| 任务 | 稳定 task_id；需求/批准决定及可观察行为；允许修改路径与禁区；输入/输出接口；前置依赖、共享资源及冲突；验证目标、实际入口、回归与完成条件；责任人、停止条件及证据位置 |
| 总进度 | 计划与授权、任务工作/控制状态、已批准决定、待决事项、快照和证据引用、稳定 issue_id 与实际修复失败次数、活动执行/子进程、下一步 |
| 交付身份 | `(requirements_rev, snapshot_id, policy_rev)`；需求版本、实现/测试/配置快照、适用规则内容版本。实际模型、档位、工具/权限/环境及 `package_id` 为证据前提 |
| 任务交接信息 | 复杂委派时记录 `case_id / task_id / attempt_id / requirements_rev / policy_rev / package_id / input_snapshot_id / coordinator_epoch`；worker、允许材料/写入、共享资源、完成/停止条件 |
| worker 返回 | 原任务交接信息中的身份、output_snapshot_id、实际 diff、命令/真实结果、证据位置、缺口、遗留进程与待继续位置 |

任务需求版本绑定其相关子集。整体变更后可保留已证明需求、依赖和规则前提等价的无关任务，并映射到新交付；受影响任务证据失效。不能只凭 Git 提交号标识脏工作区。`attempt_id` 每次新执行唯一，不重置 issue 的失败次数；协调标识不提供访问控制。

工作状态为 `PLANNED → IN_PROGRESS → IMPLEMENTED → VERIFIED`；控制状态另记 `ACTIVE / PAUSED / BLOCKED / CANCELLED` 及原因。暂停/取消保留产物与历史；证据失效使 VERIFIED 回到 IMPLEMENTED。整体为 `NOT_READY / READY_FOR_ACCEPTANCE / ACCEPTED`，条件见 [工作流契约](workflow-contract.md)。

## 应有检查与实际目标

验证前由主会话根据冻结的现行规则、改动类型和批准验收要求生成 `expected_checks`。逐条核对规则与验收的去向，适用独立审查同时核对语义完整性；worker 自选 lint 清单或 `complete=True` 不能代替。

规划、执行和审查承接同一份清单，在既有记录中维护本次验证范围、不测项、有效证据的复用依据及补做/重跑原因。按批准的行为及相关执行分支，核对实际入口、执行方和结果/状态回写；模块或文件分组通过不能代替这些连接的验收。关键不确定性在真实入口、集成或交互时，先核对现有请求构造、夹具和必需输入，优先取得能回答该问题的最小真实证据，再补其余必要验证；已有等价证据直接复用，用户指定的审查/测试顺序继续遵守。

完成一组相关修改后运行目标检查与受影响回归；定位、复现所需的快速检查可随时进行。补做、重跑或扩大检查前，说明相关变化、失败或未解决验收项，以及这次检查将填补的具体证据缺口；仅有“尚未验收”不足以重跑，证据失效范围按下文规则判定。批量补测或重建环境前，先核对所需输入、目标环境和可信报告能否取得；缺失时先查可用的获准替代方式，不用增加无关用例或重复打包代替。范围内仍可修复或补证的工作继续；已无可继续的独立获准工作时，交付已有结果、具体阻断、所需材料或决定及恢复条件，保持 NOT_READY。必要检查通过且没有未解决验收项后交付，不因阶段切换重复检查或顺带补无关历史测试。

| check_id | 规则/验收原文出处与版本 | 范围和行为目标 | 必需或 N/A 及预先理由 | 检查方法与运行前目标身份 | 实际证据/结论 |
| --- | --- | --- | --- | --- | --- |
| 稳定编号 | 可核对来源、条款与内容版本 | 检查对象及业务目标 | 保留原强制/推荐/参考等级和适用条件，说明本次是否必需；不在失败后改口 | 人工/静态/运行等方法；测试注明框架/套件/用例/参数集合 | 快照、attempt、结果与缺口 |

按本任务相关项目依据选择条款，在现有字段记录适用性，不新增全量规范表。规范等级不等于检查方法：不是每条规范都要写单测，也不能以静态通过替代需要真实入口或交互的证据。实施改变接口、数据模型或失败语义时，同步原设计及受影响任务、检查目标与证据前提，保留原决定和失效记录。

先确定业务目标；测试写好后、目标验证运行前固定实际身份、筛选条件、动态参数集合或可核验发现规则。必要时另记有依据的可选目标，不能把 required 降为 optional 来消除失败。改名必须有对应映射，改行为重验受影响证据。

核对 expected_checks、实际发现、实际执行和报告明细：

- 必需目标 missing、skip、disabled、aborted 或参数不全均不能完成；未观察到业务失败记 UNVERIFIED，已观察到断言失败/错误保留 FAIL，另列缺失项。
- 预先有依据的可选/N/A 跳过不机械阻断必需完整性；实际执行的失败仍保留，不能以可选擦掉 FAIL。
- 报告错快照、重复身份、混并 attempt、数量矛盾、无法解析或只有汇总时补可信明细/定向验证，不凭汇总成功放行。
- 检查集合缺失、空集合或全 N/A 不能让开发交付通过；至少保留适用的范围/内容核对和最终集成要求。

## 有效证据与快照

每项证据记录任务/需求/检查、范围与比较基线、实现/测试/相关配置及必要依赖版本、真实命令或操作、时间/环境/退出码、原始日志引用、测试失败/错误/跳过与目标明细、结论及限制。`PASS / FAIL / UNVERIFIED / INCONCLUSIVE / NOT_APPLICABLE` 分开；dms-test-gate 评审结论继续使用其 PASS/FAIL/INCONCLUSIVE。

快照包括相关暂存、未暂存、未跟踪文件、夹具、构建配置/锁定依赖和影响结果的生成输入。排除自身 progress、日志、报告及明确不参与执行的构建输出，避免记录证据使自身失效；真正参与执行的生成代码/配置不得排除。路径不得越界、跟随未授权符号链接或纳入凭据。内容哈希只证明内容身份，不证明命令执行或证据可信。

运行时保持相关快照稳定；发生并行写入则补核对/重验，不能直接绑定到最终代码。主会话核对宿主原始执行记录及实际报告，不把 worker 自写摘要当日志。无法确认来源或环境标未验证。

实现、测试、配置/依赖、业务契约、适用规则/角色或必要环境变化后，先撤销当前最终 PASS，列出受影响目标、实际入口、断言/夹具、实现及依赖，重验和复审相应范围；新增或改变行为同时更新对应场景。共享守卫、helper、装配条件、公共接口或依赖变化须追到相关消费者及接入方式；边界不明时扩大到相关消费范围，不能只检查修改模块。

前提未变且足以支持当前目标的证据可复用，包括同一任务中的未受影响部分，须说明范围及前提为何仍等价；日志、报告及已证明无关的文案不使执行证据失效。补证后重新核对完整必需清单、未决问题及最终集成快照，形成新版本结论，不自动恢复旧 PASS。保留旧失败、存活变异和审查发现，关闭须有处置及新证据；无关存量失败有依据地单列，不在失败后改为 optional。

测试规则修订 `test-gate-2026-10-25-r3` 沿用上述按影响重验；历史结果保留原 `policy_rev`，不追溯改判。规则版本变化须核对原证据与新要求是否相容，不能只改包号就视为有效。

## 新增代码覆盖率

正式交付的新增可执行代码须有有效测试证据。先按实际职责、交付用途和消费者确定默认验收方法，在既有 `expected_checks` 中记录本次范围、批准目标及依据；需要数值证据时再明确统计对象、比较基线、计量能力和报告来源。可行性实验按[工作流契约](workflow-contract.md#授权与阶段)处理，不因文件位于临时目录或被称为“原型”就排除实际交付代码。

| 产物职责 | 默认验收要求 |
| --- | --- |
| 正式应用及业务共享库 | 保留现行新增代码单测覆盖率 **≥80%**、本节计量规则及行为验证要求 |
| 发布、部署、运维编排，以及专用于该流程的解析、配置、守卫和状态辅助逻辑 | 按行为、风险及适用集成证据验收，不设统一行覆盖率阈值；可信覆盖率作为发现遗漏的辅助证据 |

分类不由语言、后缀、目录、名称、纯函数或复用次数单独决定。Python 部署工具与 Shell 按相同职责判断；产品中的发布 API、业务服务及被应用消费的共享库仍按应用要求。流程内部 helper 随其操作流程验收，不逐函数申请数值例外，也不为统计比例拆分真实入口；混合变更按实际责任边界区分，不能在看到结果后改分类消除失败。

行为验收从需求/批准契约核对本次改变的行为、直接不变量和受影响回归，在真实被测入口验证关键结果、边界、拒绝及副作用；恢复、并发和回滚等机制按实际影响选择，不设固定场景全集、案例数或“场景覆盖率100%”。按 dms-test-gate 核对测试有效性，具体漏检疑点须补证；mock 不证明它替代的机制。L3 的对应真实入口/集成证据、必要独立复审、测试身份、实际结果及失败历史继续保留。复审先对照需求与改动核场景，不能以自行列出的清单全绿证明充分。

编排脚本已有可信报告但低于80%时，比例本身不机械导致 FAIL；仍须核对未覆盖部分是否对应缺少证据的必需行为，有缺口就补证，已有有效集成证据或不适用时说明依据。高比例也不能解除行为缺口。没有可靠数值时记录“覆盖率未计量”及原因，不要求为辅助指标反复证明不存在可用工具。

对仍适用数值验收要求的部分，按以下计量规则处理；明确约定的验收要求按下文保留。

| 情况 | 验收方法与结果 |
| --- | --- |
| 有适用工具，能可靠取得执行命中和可执行范围 | 使用可信报告核对新增代码覆盖率 ≥80%，同时完成行为验证；低于阈值为 FAIL |
| 工具未安装、权限/配置受限、采集执行报错、报告缺失或范围不明，尚无方法不可靠的具体证据 | 补齐环境、范围或报告，缺口记 UNVERIFIED；不能仅凭这些问题转为不可计量 |
| 有具体证据说明目标代码缺少可靠的执行映射或可执行分母计量手段 | 在对应检查记录“行为验收（覆盖率未计量）”、范围、能力限制及证据，按下述行为要求判断；不强求百分比 |
| 指标范围内没有新增可执行代码 | 有依据地记 NOT_APPLICABLE，仍完成适用内容或行为检查 |

计量能力按目标语言和实际执行方式核对，复用已有工具说明、校准和报告；必要时只用最小样本确认具体限制，不要求重复全网检索或为单次任务新建统计平台。工具能安装、能运行或已有成熟工具，不单独证明本次执行方式可可靠计量；仅有安装、权限、采集执行报错或报告缺失，也不能证明不可计量。未能区分方法的可靠性限制与环境故障时仍记 UNVERIFIED。

新证据表明当前计量方法不可靠时，先将已知反例对应到本次代码和实际执行方式，界定受影响范围并核对已有行为证据，再提出继续计量或调整验收方法的具体方案与推荐。不能由一个反例或若干工具失败推断整种语言或本次全部代码均不可计量。继续工具试验须有能解决已知问题的具体新依据；没有新依据时，不重复校准或继续扩大工具试验，按[工作流契约](workflow-contract.md#授权与阶段)交付已有结论、具体方案与推荐及所需决定。

“补测试、查看覆盖率、出测试报告”不自动新增百分比门槛。“提供覆盖率报告”产生数值报告交付责任，但不自动成为行为门禁前提；无法可靠取得数字时，分别说明报告未交付及行为门禁状态，不能用行为报告冒充数值报告或宣称整个请求完成。适用强制条款或本次明确约定“达到80%”“数值报告是验收前提”的，该要求持续有效；仍须做上述适用性评估，调整目标须由有权者明确批准。

获准替换数值门槛或报告交付要求后，记录新需求版本、替代交付物和精确范围，按新版本核对必需检查；不继续用该范围已被替换的数值条件阻断，也不自动改判 PASS。其他未被调整的要求继续执行，历史失败和旧结论保留。

默认行为验收或有依据的不可计量处理都不减少行为范围。对应必需行为、证据和复审有效完成且没有未解决失败时，才能形成新版本 PASS；必要依据或行为证据不足仍为 INCONCLUSIVE，实际不合格保留 FAIL。数值未计量时 `covered/total` 保持未知，不写零、100% 或无代码 N/A；未设置数值门槛、采用行为验收或不可计量均不能使 `no_code_applicable` 变为 true。

混合代码逐部分记录职责、方法和数值是否必需，不用编排或 jq 的处理方式免除应用/业务库的要求，也不能用 Shell 调用行命中证明 jq 内部分支执行。已列场景通过不能换算成代码覆盖率。没有新增 Java 只说明相应 JVM 指标不适用，整体无代码 N/A 仍须有范围依据。

计量部分优先复用项目已有可信报告，JVM 代码可用 JaCoCo/Sonar；记录真实新增可执行范围、指标定义、分子分母、排除项、版本及来源。类级 LINE、整体覆盖率、扫描排除与覆盖率排除不能混用。用未四舍五入的原值比较：79% 或 79.9% 不通过，恰好 80% 只代表此项达标。统计值须为实际整数（布尔不作整数），满足 `0 ≤ covered ≤ total`；`no_code_applicable` 须为布尔且表示已确认无适用新增代码的事实。该断言为 true 却有正分母，先记 UNVERIFIED；只有范围有效、covered/total 均零且无代码事实已确认才按无代码记 NOT_APPLICABLE，不能写 100%。这些一致性判断不证明报告来源或新增范围正确。

## 记录更新

主会话唯一写总记录，worker 仅写各自获准证据目录。记录 `record_rev` 与协调会话，核对旧版本后写临时文件并原子替换；这只防截断，不是多会话锁。关键决定、状态转换及对应证据形成后及时更新，交接和暂停前核对当前状态，不等最后汇总才纠正已知过期结论；损坏时保留原件，从实际文件与日志重建并标来源。停止、接管和跨包恢复按 [执行策略](execution-policy.md)，不能仅凭记录时间认定旧执行已经结束。
