# 方案检查

可独立调用；不要求先启动或加载总流程。

本 Skill 只检查或改进方案材料；除非请求另有明确授权，不修改代码、不启动测试、不提交或发布。小改动可用一段任务说明表达范围、验证和完成条件，不强制创建计划文件。

按 [工作流契约](../dms-dev/references/workflow-contract.md#授权与阶段) 核对方案的目标、范围、与现有流程的关系及验收条件是否符合用户已明确的需求和后续修订。已有有效决定直接承接，不重复确认；方案自述或工具、实现路径不能代替需求依据。再按 [DMS 项目依据](../dms-dev/references/dms-project-context.md) 核对相关调用链和规范。技术设计由主会话产出，本 Skill 检查设计是否足以指导本次实现，不把缺设计的问题直接交给任务拆分。检查方案是否：

- 使每项验收要求都能对应交付物和验证；
- 设计深度符合本轮请求，架构职责与取舍、详细实现契约、实施任务可分别定位；完整技术方案不以任务清单代替详细设计，同一契约不在多处重复维护，小任务不强制拆文件；
- 在存在独立行为、接口或责任边界时才拆分，并写明依赖、共享资源、实施顺序和各自完成条件；
- 写清范围、禁区、输入输出和验证前提，不编造尚未调查到的文件、接口或命令；
- 改动位置及消费者与实际模块/调用链一致，数据、租户和失败边界清楚；采用的规范保留来源、原等级与适用条件，灰度和非功能要求只覆盖本次相关项；
- 持久化、重试、恢复及相应验收与已确认的可靠性取舍一致，业务成功、留痕和通知送达的保证不混用；未决定的实质取舍先对齐，不将完整恢复机制默认为需求；
- 复用仍有效的计划、预检与证据，不另建竞争版本；
- 实施中改变接口、数据模型或失败语义时，已同步原设计、任务和受影响验收；探索任务有明确问题、结论与限制，不被当作完成实现；
- 区分事实缺口与成员决定。先查事实；仅把业务语义、范围、关键取舍或验收的实质分歧交由成员对齐。

交付前清除占位符、矛盾、遗漏的验收映射和无法执行的范围描述。输出可执行的方案或问题清单，并标注已确认、待确认和未验证内容。
