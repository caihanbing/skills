## 快速上下文

该功能通过 `work-summary-goals/SKILL.md` 为 Codex 提供季度目标、季度总结和年度总结的写作规则，并通过 `work-summary-goals/references/style-guide.md` 保持用户既有中文文稿结构和语气。

入口是 Codex skill 自动发现或显式调用；界面元数据位于 `work-summary-goals/agents/openai.yaml`。当前实现是无运行时状态的提示与参考文件集合，核心约束是当前周期材料决定事实，历史材料只用于风格参考。

## 目标与边界

### 目标

- 根据零散工作项生成结构化季度目标。
- 根据周总结和季度目标生成事实可回溯的季度总结。
- 根据四个季度总结生成年度总结，并在材料缺失时先确认。
- 延续用户既有的主题层级、目标结构、措辞和总结风格。

### 范围内

- 支持季度目标、季度总结和年度总结三种模式。
- 支持从相对周期推导同一编号规则下的下个季度，例如 `2026.03` 到 `2026.04`。
- 支持将工作项扩展为直接相关的方案、开发、联调、验证、文档和交付任务。
- 支持把同一任务的多个周报动作合并为一条成果，并保持目标层级。
- 支持在材料缺失、状态冲突或年度季度不完整时暂停写作并提问。

### 范围外

- 不从历史范例中补充当前周期的项目、版本、地区、数据源、指标或成果。
- 不提供后端 API、数据库模型、迁移脚本或业务系统运行时能力。
- 不在用户未提供依据时新增接口、架构、算法、指标、日期或责任人。
- 不把未参与或仅有缺失记录的目标自动改写为未完成事项。

### 不变量

- 当前周期材料决定总结事实，历史材料只决定写法。
- 用户目标的一级标题和层级不能被擅自新增、提升或删除。
- 目标中的具体子项必须被覆盖；相关实施动作应合并而非机械复述。
- “上线、发布、交付”等强动作必须有当前输入依据。
- 正式稿信息完整后只输出可直接粘贴的文稿，不附分析说明。

## 业务行为

- 用户提供当前周期任务、周总结或季度总结，并可提供历史范例作为风格参考。
- 季度目标模式按工作主题输出 `目标` 和编号条目。
- 季度总结模式保留用户目标层级，输出 `目标`、`成果` 及三个总结段落；后两段为连贯文字。
- 年度总结模式要求四个季度材料齐全，并输出年度固定段落。
- 不同历史文稿不会改变当前材料的事实优先级。

## 架构与代码地图

- `work-summary-goals/SKILL.md` — 模式路由、事实边界、目标扩展、澄清门槛和输出契约。
- `work-summary-goals/references/style-guide.md` — 历史文稿结构、主题命名、句式和目标扩展检查项。
- `work-summary-goals/agents/openai.yaml` — 界面名称、短描述、默认提示和自动调用策略。

## 核心流程

1. 识别请求属于季度目标、季度总结或年度总结。
2. 区分当前周期材料、当前目标材料和历史风格材料。
3. 季度目标按工作项扩展直接相关的实施链路；总结按目标归属合并事实。
4. 检查周期、范围、状态、材料完整性和前后表述冲突。
5. 存在阻塞歧义时只提问并暂停写作；信息完整后生成正式稿并执行事实回溯自检。

## 异常与边界条件

- 请求未说明文稿类型 — 先确认类型 — 避免套用错误结构。
- 季度总结缺少本季度目标 — 索要或确认目标 — 不从周总结反推目标。
- 年度缺少任一季度材料 — 停止生成完整年度稿并索要材料 — 不把“暂无材料”写成事实。
- 周报状态冲突 — 先请求确认 — 不把进行中升级为完成或上线。
- 工作项包含具体子项 — 全部纳入目标 — 不只保留上位名词。

## 并发与幂等

## 关键决策

### 事实与风格分离

- **决定**：当前周期材料决定事实，历史材料只用于风格。
- **原因**：避免旧版本、项目和成果被迁移到新文稿。
- **取舍**：保留历史文风复用能力，同时禁止历史事实自动复用。
- **证据**：`work-summary-goals/SKILL.md` 的核心原则和事实边界。

### 单一维护源与自动发现

- **决定**：仓库 `work-summary-goals/` 是维护源，`~/.codex/skills/work-summary-goals` 使用符号链接。
- **原因**：满足仓库维护和 Codex 自动发现两个入口，避免双份内容漂移。
- **取舍**：自动发现路径依赖本机符号链接，但仓库内容保持单一来源。
- **证据**：仓库文件地图和当前文件系统链接检查。

### 目标扩展边界

- **决定**：目标应覆盖工作项的直接实施链路，但不得新增未经提供的接口、架构、算法、指标或责任人。
- **原因**：用户需要目标比原始工作项更完整，同时要求不凭空扩展范围。
- **取舍**：允许补充联调、验证和交付动作，禁止把推测写成既定技术方案。
- **证据**：`work-summary-goals/references/style-guide.md` 的目标扩展检查项。
