## 快速上下文

`codefree/SKILL.md` 规定 Codex 交接与验收、CodeFree-O 实现与修正的分工；`codefree/scripts/runner.py` 管理任务记录和调用，`codefree/references/cli.md` 说明操作与恢复。验收依据实际变更和验证结果。当前支持结构化任务清单、完整交接与增量反馈；Codex 在执行结束后独立审查。

## 目标与边界

### 目标

- 委托执行已有计划，通过审查反馈持续修正，直至满足验收标准或遇到阻塞。

### 范围内

- 整理计划和授权、记录工作区基线、调用模型、审查结果、续接或重建会话。

### 范围外

- 不替用户扩大授权，不保证模型服务和不同版本 CLI 始终可用，不统计或限制 CodeFree-O 额度。

### 不变量

- 优先使用用户指定模型，默认 `glm5.3`；解析失败或歧义时停止，不擅自替换。
- 新建会话使用任务标题，续接使用明确会话 ID；已有修改须经独立审查确认保留。

## 业务行为

- 保存已确认计划、版本化子任务清单、验收项、授权范围和验证方式；首次、计划修订和重建时合成完整交接，续接传递增量反馈。
- Codex 检查产物与基线，记录通过、失败或阻塞及证据，失败时反馈具体问题并优先续接原会话。
- 实质进展以验收项通过、问题复验关闭或阻塞解除并推进验证为依据；连续三轮无进展时暂停。正常续接使用增量上下文，旨在减少 Codex 消耗，实际额度变化尚未量化。

## 架构与代码地图

- `codefree/SKILL.md` — 入口、职责、审查与停止规则。
- `codefree/references/cli.md` — CLI 参数、审查与恢复操作。
- `codefree/scripts/runner.py` — 计划、快照、运行状态、锁与审查记录。
- `codefree/scripts/events.py` — JSON 事件及会话 ID 校验。
- `codefree/tests/` — 模拟 CLI 和临时 Git 仓库测试；`codefree/agents/openai.yaml` 提供界面元数据。

## API、事件与任务

- `runner.py` 提供 `prepare`、`run`、`record-review`、`status` 子命令；`prepare` 要求 `--tasks-file` 指定版本化 JSON 清单，运行输出 JSON 摘要，详细操作见 `codefree/references/cli.md`。
- 调用 `codefree-o models` 解析模型，首次解析后禁止切换，使用 `run --dir ... --model ... --format json` 从标准输入传递交接。新建传 `--title`，续接传 `--session`；运行器查询项目会话列表验证新会话标题。
- `events.py` 要求事件中的 `sessionID` 唯一且与指定续接会话一致；无效 JSON、错误事件、缺失或冲突 ID 导致失败。

## 数据模型与迁移

无业务数据库和迁移。运行记录存于项目外，包括版本化计划、`state.json`、基线与轮次快照、交接、事件、错误和审查记录。新记录标记 `version=2`，旧记录的准备、运行和审查被拒绝；旧记录状态协调只读；缺少任务清单的 v2 记录须补齐才能执行。

## 核心流程

1. `prepare` 固定项目、任务、计划与验收信息，记录 Git HEAD、暂存及工作区差异和相关文件；非 Git 目录须提供路径清单。
2. `run` 检查工作区快照与并发锁，调用选定模型并记录进程、事件和执行后快照。
3. Codex 对照基线和验收项审查、运行适当验证，再用 `record-review` 保存结论及进展。
4. 通过后禁止再次运行；失败可续接。异常轮次经审查后可凭证据显式重试或重建；连续三轮无进展后暂停。

## 异常与边界条件

- 模型不可用或匹配歧义、会话标题验证失败、JSON 异常或进程非零退出：保留证据并停止自动续接。
- 工作区轮次外变化、已有文件删除或原有暂存差异变化：停止派发或审查，供人工检查。
- 中断后可使用 `status --reconcile`；PID 缺失时需独立确认没有遗留进程。协调后进入待审查状态；审查及恢复证据齐备后可显式续接或重建。

## 并发与幂等

- `runner.py` 使用记录锁和项目锁阻止同机同记录操作或同项目的准备、运行、审查及协调并发；锁文件位于系统临时目录，项目锁描述符传给子进程。
- 工作区快照比较可发现轮次间变化；执行或恢复不会自动重置工作区。不存在共享队列或跨机器锁。

## 安全与权限

- 运行记录目录限制为用户私有，仍可能包含源代码及交接内容，需按本机要求保护。
- 参数以独立数组传递，交接经标准输入；运行器当前每次自动传入 `--auto`。技能说明要求派发前确认授权覆盖自动批准；调用记录如实反映自动批准。
- 运行器检查已记录文件是否删除和原有暂存差异是否改变；同一文件内原有修改是否保留仍由 Codex 核对。

## 配置与依赖

- 依赖 Python 标准库、Git（Git 工作区）、`codefree-o` CLI 与可用模型服务；使用 Unix `fcntl`，不声明 Windows 兼容。
- 本机验证过 CodeFree-O 1.10.1；模型列表和 CLI 参数每次使用前核实。
- 本机安装入口为指向仓库维护源的软链接；仓库不自动安装该链接。

## 可观测性与运维

- 每轮保存交接、模型和计划版本、事件、错误输出、进程退出结果、快照及审查证据；敏感原始文件不应直接披露。
- `status` 展示保存的状态；异常或中断后先检查证据再重试。此功能无运行服务、数据库迁移或服务重启步骤。

## 关键决策

### 实现与审查分工

- **决定**：实现和修正交给 CodeFree-O，Codex 独立审查与验证。
- **原因**：依据实际产物而非执行者自述判断验收。
- **取舍**：需要保存交接和会话证据并逐轮审查。
- **证据**：`codefree/SKILL.md`、`codefree/scripts/runner.py`。

### 运行记录与恢复

- **决定**：使用仓库外运行记录、进程和会话标识、基线快照及显式恢复证据。
- **原因**：支持中断后的检查并减少重复执行。
- **取舍**：记录可能包含源代码；同文件内容保护和无 PID 的遗留进程仍需人工确认。
- **证据**：`codefree/scripts/runner.py`、`codefree/references/cli.md`。

## 已知问题与后续工作

### 执行环境与用量限制

- **影响**：宿主等待方式和账户用量统计不由运行器控制，无法保证等待期间零额度消耗。
- **当前处理**：技能规定静默等待并只在结束或异常后读取证据；CodeFree 默认自动批准，派发前需确认授权。
- **后续动作**：在可用额度计量的环境比较实际用量；继续评估中断和真实服务异常。

### 模型服务和 CLI 版本依赖

- **影响**：模型列表、权限与 CLI 事件可能随环境和版本变化。
- **当前处理**：执行前检查版本、帮助与模型，校验事件及标题。
- **后续动作**：CLI 升级后重新运行隔离仓库兼容性验收。

### 基线与中断恢复的人工判断

- **影响**：无法仅凭脚本证明同一文件内用户改动完整保留或缺失 PID 时没有遗留进程。
- **当前处理**：Codex 对照快照审查，并在协调无 PID 中断前独立确认进程状态。
- **后续动作**：按实际运行证据评估是否需要更精确的自动检测。
